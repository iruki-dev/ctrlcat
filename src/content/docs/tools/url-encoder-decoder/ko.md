## URL 인코더 / 디코더

### 이 도구는 무엇인가요

URL은 정해진 범위의 문자만 담을 수 있습니다. 공백이나 앰퍼샌드처럼 그 범위를 벗어나는 문자는 퍼센트 기호와 두 자리 16진수로 다시 쓰여야 합니다. 이 변환을 퍼센트 인코딩이라고 부르며, `hello world`를 `hello%20world`로 바꾸는 것이 바로 이 과정입니다.

이 도구는 텍스트를 양방향으로 변환합니다. 내용을 붙여넣고 인코딩할지 디코딩할지 고른 다음 결과를 확인하면 됩니다. 모든 처리는 브라우저 안에서 이루어집니다.

### 언제 쓰면 좋은가요

API 호출을 점검하면서 쿼리 문자열이 인코딩된 뒤 서버가 실제로 무엇을 받았는지 확인해야 할 때 쓸 수 있습니다.

공백이나 따옴표, 더하기 기호가 들어간 검색어를 링크에 담아야 해서 URL에 붙여넣기 전에 해당 값을 인코딩해야 할 때 유용합니다.

메일에서 복사한 긴 추적 링크에서 `%3F`와 `%3D` 뒤에 가려진 캠페인 파라미터를 읽어내고 싶을 때 도움이 됩니다.

두 번 인코딩된 리다이렉트 주소를 받아 한 겹씩 벗겨내며 확인하고 싶을 때도 쓸 수 있습니다.

### 사용 방법

입력란에 텍스트를 붙여넣거나 직접 입력합니다. 입력란 위의 버튼에서 인코딩과 디코딩 중 원하는 방향을 고릅니다.

적용 범위를 고릅니다. 컴포넌트는 예약 문자를 모두 인코딩하므로 쿼리 값 하나나 경로 조각 하나를 다룰 때 적합합니다. 전체 URL은 슬래시, 물음표, 앰퍼샌드 같은 구조 문자를 그대로 두기 때문에 주소 전체를 그대로 쓸 수 있습니다.

결과는 입력하는 즉시 아래에 나타납니다. 결과를 클립보드에 복사하거나, 교체 버튼으로 결과를 다시 입력란으로 옮겨 한 번 더 변환할 수 있습니다.

### 자주 묻는 질문

**컴포넌트와 전체 URL은 어떻게 다른가요?**
컴포넌트는 입력한 텍스트를 하나의 값으로 보기 때문에 `&`, `=`, `/`, `?` 같은 문자도 모두 인코딩합니다. 전체 URL은 주소 전체를 받았다고 가정하고 이런 문자를 그대로 두며, 링크를 깨뜨릴 만한 문자만 인코딩합니다. 쿼리 파라미터 하나를 인코딩한다면 컴포넌트를 고르십시오.

**왜 공백이 %20이 아니라 더하기 기호가 될 때가 있나요?**
예전 HTML 폼 전송 방식은 공백을 `+`로 인코딩하고, 퍼센트 인코딩은 `%20`을 씁니다. 두 방식 모두 실제로 쓰이고 있습니다. 이 도구는 인코딩할 때 `%20`을 쓰며, 디코딩할 때는 더하기 옵션을 켜면 `+`를 공백으로 읽습니다.

**디코딩에 실패했다는 것은 무슨 뜻인가요?**
퍼센트 기호 뒤에는 유효한 16진수 두 자리가 와야 합니다. 텍스트에 홀로 남은 `%`나 잘린 시퀀스가 있으면 어떤 바이트를 의도했는지 알 수 없으므로, 도구는 추측하지 않고 입력이 잘못되었다고 알립니다.

**입력한 내용이 어딘가로 전송되나요?**
아니요. 변환은 브라우저에 내장된 기능만으로 전부 처리됩니다. 어떤 내용도 페이지 밖으로 나가지 않습니다.
