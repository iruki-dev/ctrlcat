# i18n 시스템

현재 locale: `en` (기본, URL prefix 없음) · `ko` (`/ko/` prefix)

## 브라우저 언어 따라가기

`SeoHead.astro`의 인라인 스크립트가 영어 페이지를 열었을 때 브라우저 첫 번째 언어가 한국어이면 같은 페이지의 `/ko/` 주소로 옮깁니다. 언어 전환 링크(`data-locale` 속성이 붙은 `<a>`)를 누르면 그 선택을 `localStorage`의 `ctrlcat-lang`에 저장하고, 저장된 값이 있으면 브라우저 언어보다 우선합니다. 한국어 페이지에서 영어로 자동 이동하는 일은 없습니다. 새 언어 전환 링크를 만들 때는 `data-locale={l}`를 붙입니다.

포털 빌드(`portal/main.tsx`)도 같은 규칙으로 언어를 고릅니다.

문자열은 두 갈래로 관리합니다.

| 어디서 쓰나 | 어디에 두나 | 읽는 법 |
|---|---|---|
| Astro 레이아웃·뷰·사이드바 | `src/i18n/en.ts` · `ko.ts` | `t(lang).key` |
| React 툴·게임 컴포넌트 | 컴포넌트 파일 안의 `messages` 객체 | `useMessages(messages)` |

## Astro 쪽 헬퍼 (`src/i18n/index.ts`)

```ts
import { t, localePath, switchLocalePath, localize, locales, localeLabels } from "../i18n";

t("ko").tools.pageTitle            // → "웹 도구"
localePath("/tools/", "ko")        // → "/ko/tools/"
switchLocalePath(Astro.url, "en")  // 현재 페이지의 EN 주소
localize(entry, lang)              // → { title, description } (localizations 폴백 포함)
localeLabels.ko.short              // → "KO"
```

`en.ts`가 타입의 기준이고 `ko.ts`는 같은 모양을 모두 채워야 합니다. 빠진 키가 있으면 빌드가 실패합니다.

## React 쪽 (`src/i18n/react.tsx`)

`ToolRenderer`·`GameRenderer`가 `LangProvider`로 감싸 주므로 컴포넌트는 props 없이 언어를 압니다.

```tsx
import { useMessages } from "../../i18n/react";

const messages = {
  en: {
    input: "Input",
    count: (n: number) => `${n} words`,
  },
  ko: {
    input: "입력",
    count: (n: number) => `${n}단어`,
  },
};

export default function WordCounter() {
  const m = useMessages(messages);
  return <span>{m.count(3)}</span>;
}
```

규칙:
- `ko`는 `en`과 키·함수 시그니처가 같아야 합니다 (`useMessages<T>`가 타입으로 검사).
- 숫자·단어가 섞이는 문장은 함수로 둡니다. 어순과 복수형이 언어마다 달라서 문자열을 이어 붙이지 않습니다.
- 에러·알림 상태는 문자열 대신 코드(`"empty" | "invalid"` 등)로 저장하고, 렌더할 때 `m.errors[code]`로 바꿉니다. 언어를 바꿔도 메시지가 따라 바뀝니다.
- 날짜·숫자는 `Intl.DateTimeFormat` · `Intl.RelativeTimeFormat` · `toLocaleString(lang)`을 씁니다 (`useLang()`).
- 변수 이름 `m`은 메시지 전용입니다. 컴포넌트 안에서 다른 용도로 `m`을 쓰지 않습니다.

게임은 공통 라벨(시작, 다시 하기, 점수, 최고 기록 등)을 `src/games/lib/messages.ts`의 `common`에서 가져와 펼칩니다.

```tsx
import { common } from "../lib/messages";
const messages = {
  en: { ...common.en, intro: "..." },
  ko: { ...common.ko, intro: "..." },
};
```

## 콘텐츠 제목·설명 번역

`.md` frontmatter의 `localizations` 필드:

```yaml
localizations:
  ko:
    title: "한국어 제목"
    description: "한국어 설명"
```

뷰는 `localize(entry, lang)`로 읽습니다.

## 문서 본문 번역

`src/content/docs/<kind>s/<slug>/ko.md`:

```yaml
---
kind: tool   # 또는 game
ref: word-counter
lang: ko
---

## 이 도구는 무엇인가요

본문...
```

페이지 제목은 레이아웃이 이미 보여 주므로 본문 첫 줄에 도구·게임 이름만 있는 제목을 다시 넣지 않습니다. 없으면 영어 본문으로 폴백합니다 (`DocArticle.astro`).

## 새 locale 추가

1. `src/i18n/index.ts`의 `Locale` 타입, `locales`, `localeLabels`에 추가
2. `src/i18n/<locale>.ts` 생성 (`en.ts`와 같은 모양)
3. `src/i18n/react.tsx`의 `useMessages` 시그니처와 모든 컴포넌트 `messages`에 새 키 추가
4. `src/pages/<locale>/`를 `ko/` 구조 그대로 복사하고 `lang`만 바꿈
5. `astro.config.mjs` sitemap `i18n.locales`에 추가
