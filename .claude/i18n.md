# i18n 시스템

## 파일 구조

| 파일 | 역할 |
|---|---|
| `src/i18n/en.ts` | 영어 문자열 + `Translations` 타입 정의 (소스 오브 트루스) |
| `src/i18n/ko.ts` | 한국어 문자열 (`Translations` 타입을 완전히 구현해야 합니다) |
| `src/i18n/index.ts` | 헬퍼 함수 모음, `locales` 배열 |

## 헬퍼 함수

```ts
import { t, localePath, switchLocalePath, getLang } from "../i18n";

t("ko")                            // → ko Translations 객체
t("ko").tools.pageTitle            // → "웹 도구"
localePath("/tools/", "ko")        // → "/ko/tools/"
switchLocalePath(url, "ko")        // 현재 URL → KO 동일 페이지
getLang(url)                       // URL에서 locale 추출 ("en" | "ko")
```

## 현재 locale

`en` (기본) · `ko`

URL 구조: 영어는 prefix 없음(`/tools/`), 한국어는 `/ko/` prefix.

## 새 locale 추가

1. `src/i18n/index.ts`의 `locales` 배열에 추가
2. `src/i18n/<locale>.ts` 생성 (`Translations` 타입 완전 구현)
3. `src/pages/<locale>/` 디렉토리를 `ko/` 구조 그대로 복사

## UI 문자열 번역

`.astro` 파일에 사용자 문자열을 하드코딩하지 않습니다 — 항상 `t(lang).key`를 씁니다.

새 문자열을 추가할 때:
1. `src/i18n/en.ts`에 추가 (타입도 함께 정의)
2. `src/i18n/ko.ts`에 한국어 번역 추가

## 콘텐츠 제목·설명 번역

`.md` frontmatter에 `localizations` 필드를 추가합니다:

```yaml
localizations:
  ko:
    title: "한국어 제목"
    description: "한국어 설명"
```

`[slug].astro`에서 자동으로 읽습니다:
```ts
const title = game.data.localizations?.["ko"]?.title ?? game.data.title;
```

## 문서 본문 번역

`src/content/docs/<kind>/<slug>/ko.md`를 만들면 됩니다:

```yaml
---
kind: tool   # 또는 game
ref: word-counter
lang: ko
---

한국어 본문...
```

KO 슬러그 페이지가 `getEntry("docs", "tools/<slug>/ko")`로 조회하고, 없으면 영어 body로 폴백합니다.
