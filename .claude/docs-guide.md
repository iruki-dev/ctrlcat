# 콘텐츠 문서 작성 가이드

## 대상 독자

일반 사용자. 개발자나 학생이 아닙니다. 코드, 수식, 알고리즘 설명은 쓰지 않습니다.

---

## 파일 구조 규칙

| 역할 | 파일 위치 |
|---|---|
| 영어 본문 | `src/content/tools/<slug>.md` 또는 `src/content/games/<slug>.md` frontmatter 아래 |
| 한국어 본문 | `src/content/docs/tools/<slug>/ko.md` 또는 `src/content/docs/games/<slug>/ko.md` |

**영어를 먼저 작성합니다.** 한국어 문서는 영어 문서의 자연스러운 번역·의역이어야 하며, 구조와 소제목 수가 동일해야 합니다.

---

## 문서 길이

| 유형 | 목표 분량 |
|---|---|
| 게임 문서 | 300–500 단어 (한국어는 이에 상당하는 분량) |
| 툴 문서 | 250–450 단어 |
| FAQ | 2–4 항목 |

너무 짧으면 독자에게 가치가 없고, 너무 길면 읽히지 않습니다.

---

## 구조 (게임)

```
## How it works           ← 게임 메커니즘 설명 (1–2 단락)
## [핵심 전략 또는 도전]    ← 게임의 핵심 난이도/흥미 포인트 (1–2 단락)
## [팁 또는 점수 시스템]     ← 실용적 조언 또는 점수 설명 (1–2 단락)
## Controls               ← 조작 방법 (짧게)
## Frequently asked questions ← 2–4항목
```

## 구조 (툴)

```
## What this is           ← 도구가 무엇인지 맥락 설명
## Where this is useful   ← 사용 사례 목록 (3–5개)
## How to use this tool   ← 사용 방법 설명
## Frequently asked questions ← 2–4항목
```

---

## 어조와 스타일

- 짧은 문장. 단락당 2–4문장.
- 사용자를 "you"로 지칭합니다.
- 전문 용어를 쓸 경우 첫 등장 시 짧게 설명합니다.
- 흥미로운 사실이나 맥락 — 역사적 배경, 수학적 원리, 실생활 연결 — 을 자연스럽게 녹입니다.
- 조언은 구체적으로 씁니다. "잘 하세요"가 아니라 "코너에서 시작하세요."

## 절대 쓰지 않는 것

- 코드 블록 (\`\`\`)
- 수식 또는 LaTeX
- 이모지
- 마케팅 문구 ("강력한", "완벽한", "최고의")
- 2인칭 명령형으로만 된 글머리 목록

---

## FAQ 형식

```markdown
**질문?**
한 단락으로 된 직접적인 답변.

**다음 질문?**
답변.
```

소제목이나 별도 heading 없이 **굵게** 표시한 질문 + 이어지는 단락으로 씁니다.

---

## 한국어 문서 주의사항

- 영어 본문의 직역이 아닌 자연스러운 한국어 문장으로 씁니다.
- "합니다/합니다체" (격식체) 를 사용합니다.
- 게임 용어(벽, 꼬리, 먹이 등)는 한국어 게임에서 일반적으로 사용하는 표현을 따릅니다.
- frontmatter:
  ```yaml
  ---
  kind: game   # 또는 tool
  ref: <slug>
  lang: ko
  ---
  ```
